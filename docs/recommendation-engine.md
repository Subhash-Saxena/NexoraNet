# NexoraNet Recommendation Engine (Step 8)

## 1. Recommendation Philosophy

The **Recommendation Engine** answers the primary student question:

$$\textbf{"What should I do next?"}$$

It evaluates the student's recent performance profile against curriculum prerequisite graphs and available educational assets to provide clear, actionable guidance.

---

## 2. Recommendation Categories

The engine produces seven structured recommendation types:

| Category | Typical Trigger | Action Taken |
| :--- | :--- | :--- |
| **`TOPIC_PRACTICE`** | Topic flagged as `NEEDS_PRACTICE` or `DEVELOPING` | Launches a dynamically targeted adaptive practice quiz on that topic |
| **`LAB`** | Topic needs reinforcement and has published hands-on lab sandbox | Links directly to interactive terminal lab (e.g. Subnetting Sandbox, IP Discovery) |
| **`LESSON`** | Fundamental concept requires theoretical review before retaking assessments | Links to curriculum lesson text, network diagrams, and architectural references |
| **`MOCK_TEST`** | Student demonstrates solid proficiency at current difficulty tier | Links to formal catalog mock exam (e.g., CCNA Associate, Network Defense Mock) |
| **`ADAPTIVE_TEST`** | Holistic multi-topic practice session | Compiles 20 questions balancing 50% weak, 30% developing, and 20% solid topics |
| **`DIFFICULTY_REINFORCEMENT`** | High tier accuracy is low, or lower tier requires solidification | Recommends foundational drills before advancing to harder assessments |
| **`REVIEW`** | Topic performance decay detected ($> 14$ days without practice) | Recommends quick 5-to-10 question refresher drill |

---

## 3. Prerequisite-Aware Reordering

Recommendations respect the natural networking curriculum dependency chain:

$$\text{Networking Fundamentals} \longrightarrow \text{OSI / TCP-IP} \longrightarrow \text{IPv4 Addressing} \longrightarrow \text{Subnetting} \longrightarrow \text{Routing} \longrightarrow \text{Network Defense}$$

### Prerequisite Rule Example:
If a student scores poorly on both **IPv4 Addressing** ($50\%$) and **Subnetting** ($45\%$), the recommendation engine prioritizes IPv4 Addressing first:
- Foundational addressing principles must be locked in before advanced variable-length subnet masks (VLSM) or CIDR calculations are recommended.

## 4. Explainable Rationale Guarantee

Every recommendation record generated by [`RecommendationService`](file:///c:/Users/himan/Downloads/Projects/antigravity%20NexoraNet/backend/app/services/recommendation_service.py) includes a non-empty `reason` string explaining the exact data that triggered it:

```json
{
  "id": "rec-prac-4-a1b2c3",
  "type": "TOPIC_PRACTICE",
  "title": "Practice IPv4 Subnetting",
  "reason": "Your recent IPv4 Subnetting accuracy is 52% across 10 questions.",
  "priority": "HIGH",
  "topic_id": 4,
  "topic_slug": "ipv4-subnetting",
  "recommended_difficulty": "INTERMEDIATE",
  "action_label": "Start Topic Practice",
  "action_url": "/adaptive-test?focus=4"
}
```

No vague phrases such as *"AI thinks you should study this"* are ever displayed.

---

## 5. Telemetry & Auditability

Student interaction with recommendations is tracked locally via `RecommendationEvent` records:
- Logs `user_id`, `recommendation_type`, `priority`, `action_url`, and event (`GENERATED`, `CLICKED`).
- Enables continuous measurement of recommendation effectiveness without tracking intrusive analytics.
